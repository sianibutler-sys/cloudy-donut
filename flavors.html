    Behind the scenes

    Current site vs this demo

    Flavors on cloudydonut.com

    • The page has no H1, so a screen reader lands with no page title.
    • Photo alt text reads as file names.

    Flavors in this demo

    • All 44 flavors, filterable by nut-free, boozy and made for pups.
    • Tap any donut for its deli-paper card with allergens.
    • Find your flavor: four questions, this week's box or every flavor.
    Fixed on every page
    • Text contrast meets WCAG AA. Mint text on cream measures about 1.5:1 on the current site.
    • Photos carry real descriptions, or stay silent when the donut's name sits beside them.
    • One H1 per page and no skipped heading levels.
    • A skip-to-content link for keyboard users.
    • Links that open a new tab say so to screen readers.
    • Phone numbers call on tap. Email sits in the footer of every page.
    • Search has a label. No empty header links.
    • axe-core scan: 0 WCAG 2.1 AA issues across all six pages.

    What this build does

    Yours to run, yours to keep

    1. The lineup updates itself

      Flavors, shop hours and pop-up dates live in one Airtable base. Change it there and every page follows.

    2. Every pop-up gets a flyer

      Add a city and date, and the site builds the "Cloudy Donut Presents" flyer with a live countdown.

    3. Demand, mapped

      "Bring Cloudy to my city" signups show where the next tour stop should go.

    4. Shipping, ready before launch

      The cake waitlist builds now, so the first day of shipping already has buyers.

    5. One inbox for every form

      Experiences, newsletter, tour alerts and the waitlist land in Airtable and email.

    6. Owned by Cloudy

      Custom code in Cloudy's own GitHub and Cloudflare accounts. No platform subscription.

    Forms in this concept are not connected. Nothing you type is saved.
